# P2标签兼容测试版 V6

此版本从已确认正常的原始P1工程独立复制，不覆盖稳定版本。目标是模拟官方APP
设备列表中实际存在的 `Paperang_P2`，以进入标签打印功能。

## 关键变化

- 设备名改为 `P2`，序列号使用原工程已经保留的 `P2B02004087288`。
- 保留底层硬件标识 `HME230_P2`、原固件版本和原CRC行为。
- 实现标签纸类型、最大间隙、定位送纸、打印进度、打印完成和能力查询。
- APP发来的P2位图按576点/行接收，打印前同时进行横向和纵向2/3最近邻缩放，
  转换成当前384点打印头使用的48字节/行数据。
- 修复标签模式使用 `0x21 FEED_TO_HEAD_LINE` 结束任务时只走纸、不打印缓存图像的问题。
- 标签模式先打印缓存图像，再扣除打印过程已经走过的步数，只补走到APP给出的目标位置。
- 增加输入字节数、黑点数、转换后行数和定位步数日志。
- `platformio.ini` 增加 `[platformio] default_envs = esp-wrover-kit`，默认只编译和
  上传带PSRAM的WROVER环境。
- 蓝牙接收改为逐字节状态机，不再假设类型、序号和长度字段会一次性到达；修复初始化
  偶发 `ERROR` 后APP显示已连接但不发送打印点阵的问题。
- 损坏的打印数据包会回滚该包已经写入的内容，并等待下一个 `0x02` 包头重新同步。
- 根据实测修正长度识别：APP 6.2.80对2.9/4.3/5.3 cm标签都发送
  `FEED_TO_HEAD=3840`，该参数不能用于区分长度；实际长度随位图行数变化。
- 标签总节距改为“转换后位图实际走纸步数 + 472固定非位图区步数”。实测数据对应：
  114输出行→29.0 mm、229输出行→43.4 mm、305输出行→52.9 mm。
- 保留P2 300 dpi到当前打印头约200 dpi的横纵2/3缩放，避免图像比例失真；
  不再把可打印区的3.8 cm误当成5.3 cm标签的完整走纸长度。
- 串口新增“原始行、输出行、识别节距”日志，用于核对其他标签规格。

## 风险与限制

- 这是独立实验版本，普通P1稳定版必须保留。
- 当前硬件没有标签间隙/黑标传感器，只能按APP给定尺寸打印，连续多张模切
  标签可能逐渐累积位置偏差。
- 首轮仅用短文本、小尺寸标签和中低浓度测试，避免直接打印大面积全黑图。
- 当前实测APP 6.2.80在P2标签模式使用未压缩的 `0x00` 数据，单包432字节，
  并通过 `0x21` 结束标签任务。
- 当前硬件没有标签间隙传感器，V2只能根据APP给出的目标步数定位；连续打印多张
  模切标签仍可能累积偏差，后续可按实际标签尺寸校准。

## 测试顺序

1. 使用工程指定的安卓APP 6.2.80，不升级。
2. 烧录 `esp-wrover-kit` 环境。
3. 在系统蓝牙与APP中删除旧的 `MaoPaperang/Paperang_P1` 记录，然后重新搜索。
4. 确认APP将设备识别为 `Paperang_P2` 并保持连接。
5. 先不要普通打印，直接进入标签打印，创建最短的纯文字标签进行测试。
6. 串口设为115200，确认出现 `[BITMAP]`、`[P2 SCALE]`、`[INFO]正在打印` 和
   `[LABEL] APP寻标参数=..., 原始行=..., 输出行=..., 识别节距=...` 日志。
7. 分别选择2.9、4.3、5.3、6.2、8.7 cm标签各测试一次，确认识别节距随APP
   选择改变。若实际标签“起点到下一张起点”的节距与标称长度不同，应按实测节距
   调整校准比例。

## V6-Sensor：温度保护与缺纸保护

本版在V6标签兼容基础上补齐原工程中未完成的两个安全功能。

### 1. 打印头温度检测

- GPIO：`PIN_TEMP = 35`。
- JX-2R-01机芯热敏电阻参数：R25=30kΩ，B=3950K。
- 已按上传的Mao V2硬件核对：`3.3V -> 打印头内部NTC -> TM -> R10(10kΩ) -> GND`，TM再经R11(1kΩ)串联到`GPIO35/TEMP`。
- 代码使用Beta公式由ADC换算温度，并对ADC开路/短路、异常温度进行故障判定。
- 60°C触发过温：立即关闭VH和全部STB，暂停打印。
- 温度降到55°C后自动恢复打印。
- 温度传感器故障时禁止继续加热，防止在失去温度保护时烧打印头。
- APP发送`GET_TEMP (0x12)`时，返回值不再固定为23°C，而是实时测量值。

温度换算使用板上的R10下拉电阻；当前原理图为10kΩ，对应 `src/main.h`：

```cpp
#define TEMP_PULLDOWN_OHM 10000.0f
```

R11=1kΩ只是ADC串联保护/隔离，GPIO35高阻采样时基本不参与直流分压。

ESP32 ADC存在个体误差。首次装机建议在室温稳定后对照温度计查看串口：

```text
[TEMP] ADC=xxxx R=xx.xk T=xx.xC
```

25°C附近，JX-2R-01热敏电阻应约为30kΩ；若阻值明显不对，先检查TM接线和分压电阻，不要只在软件里硬改温度偏移。

### 2. 缺纸检测

- GPIO：`PIN_PTEST = 34`。
- 逻辑：有纸=低电平，缺纸=高电平。
- 空闲状态使用40ms消抖，只在状态变化时蜂鸣，修复旧代码缺纸后不断重复长鸣、阻塞主循环的问题。
- 开始打印前强制检查一次。
- 打印过程中每一行都检查；缺纸时立即关闭VH/STB并中止当前任务。
- 安全中止后不再继续执行标签定位走纸或普通打印后的出纸动作。

已按上传的Mao V2原理图核对缺纸硬件：FPC的`PHE`进入LM393的反相输入；R22=12kΩ与R2=10kΩ产生约1.5V比较基准；LM393开集电极输出`PTEST`由R20=10kΩ上拉到3.3V，并直接接ESP32 GPIO34。

因此软件无需启用ESP32内部上拉，板上R20已经完成3.3V上拉；逻辑保持`有纸=LOW、缺纸=HIGH`。

### 3. 建议测试顺序

1. 暂时不要装打印纸，开机后应只响一次“双声”缺纸提示，串口出现 `[PAPER] no paper`。
2. 装纸后串口应出现 `[PAPER] paper inserted`。
3. 室温下观察 `[TEMP]` 日志，温度应与环境温度大致一致，25°C附近换算阻值约30kΩ。
4. 用小面积、低密度内容做首次打印；打印过程中抽掉纸，VH应立即关闭且后续不再走纸。
5. 最后再测试长图。若打印头温度达到60°C，应出现 `[SAFETY] head overheat`，冷却到55°C后自动继续。

### 4. 实机安全测试结论（2026-09-12）

- 缺纸：打印中实测可立即中止当前任务，关闭打印头，并跳过后续标签定位走纸；重新装纸后等待APP重新发送完整任务，不做断点续打。
- 过温：使用27°C停 / 25°C恢复的临时测试阈值验证通过，可重复执行“过温暂停 -> 冷却 -> 自动续打”。正式版已恢复为60°C停 / 55°C恢复。
- 正式版将常规`[TEMP]`成功采样日志限制为每1000ms最多一条，避免冷却等待阶段刷屏；传感器故障、过温、恢复、缺纸等安全事件仍立即输出。
